# mod_ptp_timer

A FreeSWITCH timer module that paces ticks against a PTP-disciplined system
clock so that media generated by other modules (RTP, AES67, `mod_ivcore`,
etc.) can be aligned to a precision time grandmaster.

## Timer name

The module registers a single timer:

```
ptp
```

Use it from any module that accepts a `timer-name` parameter, e.g.:

```xml
<param name="timer-name" value="ptp"/>
```

## Platform sources

| OS      | Source                                                                 |
|---------|------------------------------------------------------------------------|
| Linux   | `ptp4l` management UDS (default `/var/run/ptp4l`)                      |
| Windows | Native PTP provider (`%windir%\system32\ptpprov.dll`) when present     |
| Windows | PTPSync DLL fallback (default `PTPSyncNative.dll`) when native missing |

If neither Windows path is available the module **refuses to load** rather
than silently degrading to a non-PTP clock.

## Configuration (`conf/ptp_timer.conf.xml`)

```xml
<settings>
  <param name="ptp4l-socket" value="/var/run/ptp4l"/>
  <param name="ptpsync-dll"  value="PTPSyncNative.dll"/>
  <param name="debug"        value="false"/>
</settings>
```

## API

```
ptp status            # plain text snapshot
ptp status json       # single-line JSON snapshot
ptp debug on|off      # toggle verbose per-tick logging
```

Example JSON:

```json
{"state":"locked","grandmaster_id":"AA:BB:CC:FF:FE:DD:EE:FF",
 "port_state":"SLAVE","master_offset_ns":-127,"path_delay_ns":4321,
 "servo_steps":12,"source":"ptp4l@/var/run/ptp4l","sample_us":...}
```

## Events (CUSTOM)

| Subclass                    | When                                              |
|-----------------------------|---------------------------------------------------|
| `ptp::status`               | Every poll (`PTP_STATUS_POLL_MS`, default 1 s)    |
| `ptp::sync_acquired`        | Transition to `LOCKED`                            |
| `ptp::sync_lost`            | Leaves `LOCKED`                                   |
| `ptp::grandmaster_changed`  | Grandmaster ID changes while in `LOCKED`          |

All events carry these headers:

- `PTP-State` (`unknown` / `none` / `holdover` / `locked`)
- `PTP-Grandmaster-ID`
- `PTP-Port-State`
- `PTP-Master-Offset-NS`
- `PTP-Path-Delay-NS`
- `PTP-Servo-Steps`
- `PTP-Source`

## Notes

- `switch_micro_time_now()` is used for the hot tick path. On Linux it
  follows `CLOCK_MONOTONIC`; on Windows it is backed by
  `QueryPerformanceCounter`. When the OS clock is PTP-disciplined the
  monotonic deltas inherit that discipline.
- The status thread runs at `PTP_STATUS_POLL_MS` (default 1 s) and is
  intentionally decoupled from the tick path.
- The Windows native path reports a coarse `LOCKED`/`HOLDOVER` derived
  from `GetSystemTimeAdjustment` because public Win32 APIs do not expose
  the per-grandmaster offset that ptp4l does. Use the PTPSync fallback
  if you need finer telemetry on Windows.
